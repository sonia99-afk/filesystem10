# Текущий контракт данных проекта

Этот документ фиксирует текущий версионированный формат приложения. Он нужен как страховочная база для дальнейших миграций и подключения будущего API.

## Хранение

- Индекс проектов: `org_structure_projects_index_v1`.
- Данные проекта: `org_structure_project_data_<projectId>`.
- Текущая реализация: `localStorage`.
- Проект сохраняется целиком как JSON-строка, возвращаемая `snapshot()`.
- `schemaVersion: 2` — текущая версия всего документа проекта.
- Сохранение проходит через `projectDocument.serialize()`.
- Загрузка проходит через `projectDocument.hydrate()`.
- Старые snapshot без `schemaVersion` считаются legacy-версией 0.
- Миграции выполняются последовательно: `v0 → v1 → v2`.

## Структура документа

Текущий snapshot разделён на два независимых раздела:

- `project` — постоянные пользовательские данные проекта;
- `ui` — состояние интерфейса редактора.

### Раздел project

- `root` — корневой узел и вложенное дерево;
- `views` — созданные вкладки и настройки отображений;
- `properties` — реестр свойств проекта;
- `formatting.text` — форматирование текста;
- `formatting.textColor` — цвета текста;
- `formatting.blockBackground` — фоны объектов;
- `formatting.marks` — отметки объектов;
- `levelHeaderNames` — названия уровней;
- `hiddenNodeIds` — скрытые объекты.

### Раздел ui

- `selectedId` — выбранный объект;
- `treeHasFocus` — фокус дерева;
- `tableSelectedCell` — выбранная ячейка таблицы;
- `currentView` — открытый режим;
- `viewOrientation` — ориентация режима;
- `showOrdinals`, `showCaptions` — legacy-настройки, необходимые для миграции старых видов.

UI-состояние пока сохраняется вместе с документом для восстановления рабочей сессии, но оно отделено от предметных данных и может быть вынесено в пользовательские настройки без изменения структуры проекта.

На каждом уровне документа:

- неизвестные дополнительные поля сохраняются;
- входящие объекты копируются, а не используются по ссылке;
- устаревшие плоские поля после миграции не дублируются.

Пример верхнего уровня:

```json
{
  "schemaVersion": 2,
  "project": {
    "root": {},
    "views": null,
    "properties": null,
    "formatting": {},
    "levelHeaderNames": {},
    "hiddenNodeIds": []
  },
  "ui": {
    "selectedId": "node_id",
    "treeHasFocus": true,
    "tableSelectedCell": null
  }
}
```

## Узел дерева

Базовый узел имеет поля:

- `id`;
- `level`;
- `name`;
- `nameHtml`;
- `captionsBgColor`;
- `captions`;
- `children`;
- `tableProps` создаётся позднее при работе с табличными свойствами.

## Инварианты, которые нельзя сломать

1. ID каждого узла и описания уникален внутри проекта.
2. Корневой узел существует всегда и не удаляется.
3. Уровень дочернего узла согласован с положением в дереве.
4. Копирование переносит все данные узла и потомков, но создаёт новые ID.
5. Удаление ветки удаляет связанные метаданные всех её узлов.
6. Undo/Redo восстанавливает данные проекта целиком.
7. Старые сохранения проходят явную последовательную миграцию и не изменяются молча.
8. Данные интерфейса, проекта и пользователя должны быть разделены.

## Следующий целевой этап

Работа с `localStorage` помещена за интерфейс `ProjectRepository`, а документ разделён на `project` и `ui`. Следующий этап разделит крупный `autosave.js` на управляющий сервис и UI-модуль списка проектов.
